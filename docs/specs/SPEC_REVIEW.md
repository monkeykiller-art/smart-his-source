# 技术规格评审意见

> 评审日期：2026-09-18  
> 评审范围：CDSS、护理文书、LIS 三份规格草案

---

## 一、CDSS 临床决策支持系统

### 优点
- 服务划分清晰，独立部署避免污染临床服务
- 数据库设计合理，规则表与审计日志分离
- 告警分级机制（CRITICAL/WARNING/INFO）符合临床实践
- 审计日志记录覆盖原因，便于质量追溯

### 改进建议

#### 1. 性能优化（高优先级）
**问题**：药物相互作用查询需要遍历所有药品对，O(n²) 复杂度
**建议**：
- 添加缓存层：Redis 缓存 `drug_pair → interaction` 映射
- 批量查询接口：`POST /api/cdss/interactions/check-batch` 支持多患者
- 异步检查：非 CRITICAL 告警可异步返回，不阻塞医嘱提交

#### 2. 规则管理（中优先级）
**问题**：规则库维护依赖手工导入，无管理界面
**建议**：
- 新增规则管理 API（CRUD）
- 支持规则导入/导出（Excel/CSV）
- 规则版本控制和生效时间
- 规则冲突检测（同一药品对存在多条规则）

#### 3. 前端体验（中优先级）
**问题**：弹窗可能频繁出现导致医生疲劳
**建议**：
- 添加"今日不再提示"选项（针对同一药品对）
- 告警聚合：相同类型告警合并显示
- 提供告警统计面板（医生可查看自己覆盖的告警）

#### 4. 数据库优化（低优先级）
**建议**：
- `cdss_drug_interaction` 添加 `effective_date` 和 `expiry_date` 字段
- 添加 `source` 字段记录规则来源（说明书、指南、专家）
- 索引优化：复合索引 `(drug_a_id, drug_b_id, status)`

## 二、护理文书与护理计划

### 优点
- 护理闭环完整：评估→诊断→计划→记录→执行
- 量表使用 JSONB 存储，灵活可扩展
- 医嘱执行确认支持双人核对
- 权限设计合理，区分责任护士和护士长

### 改进建议

#### 1. 数据完整性（高优先级）
**问题**：护理记录表使用多个可选字段存储不同类型数据，容易混淆
**建议**：
- 拆分为多个子表：`nur_vital_sign`、`nur_intake_output`、`nur_note`
- 或使用 JSONB 存储动态字段，主表只保留公共字段
- 添加约束：`record_type = 'VITAL_SIGN'` 时 `temperature` 不能为空

#### 2. 评估自动化（高优先级）
**问题**：评估结果需要手工判断风险等级
**建议**：
- 量表评分后自动计算风险等级
- 自动生成护理诊断建议（基于评分结果）
- 触发护理计划创建提醒

#### 3. 体温单渲染（中优先级）
**问题**：体温单数据量大时前端渲染慢
**建议**：
- 后端聚合查询：按小时/天聚合，减少数据量
- 前端虚拟化渲染：只渲染可见区域
- 支持导出 PDF（卫健委标准格式）

#### 4. 医嘱执行集成（中优先级）
**问题**：医嘱执行需要与 `his-clinical` 紧密集成
**建议**：
- 使用事件驱动：护理服务发布 `OrderExecutedEvent`，临床服务订阅
- 避免直接数据库调用，通过 API 或消息队列
- 添加执行超时提醒（计划时间后 30 分钟未执行）

#### 5. 数据库优化（低优先级）
**建议**：
- `nur_record` 添加 `shift` 字段（白班/夜班）
- `nur_order_execution` 添加 `execution_location` 字段（床旁/治疗室）
- 添加软删除字段 `deleted` 和 `deleted_time`

## 三、LIS 检验信息系统

### 优点
- 样本管理流程完整：申请→采样→接收→检验→审核→报告
- 条码规则清晰，支持打印
- 危急值处理流程明确
- 工作台看板设计合理

### 改进建议

#### 1. 样本管理（高优先级）
**问题**：样本状态机复杂，缺少异常处理
**建议**：
- 添加样本作废流程（`CANCELLED` 状态）
- 支持样本合并（多个小样本合并检验）
- 添加样本流转记录表（谁在什么时间做了什么操作）

#### 2. 结果录入（高优先级）
**问题**：手工录入效率低，容易出错
**建议**：
- 支持 Excel 批量导入结果
- 预留仪器对接接口（ASTM/LIS2-A2）
- 添加结果自动审核规则（正常结果自动通过）

#### 3. 报告管理（中优先级）
**问题**：报告格式未定义
**建议**：
- 设计标准报告模板（PDF）
- 支持报告修改和补打（记录修改历史）
- 添加电子签名（CA 认证）

#### 4. 危急值管理（中优先级）
**问题**：危急值通知依赖 WebSocket，可能丢失
**建议**：
- 多渠道通知：WebSocket + 短信 + 站内信
- 超时升级：15 分钟未确认自动通知上级医生
- 危急值闭环管理：通知→确认→处理→记录

#### 5. 数据库优化（低优先级）
**建议**：
- `cli_exam_sample` 添加 `priority` 字段（常规/急诊）
- `cli_exam_result` 添加 `abnormal_flag` 字段（自动标记异常）
- 添加检验项目分组表（套餐管理）

## 四、跨规格共性问题

### 1. 服务间通信
**问题**：三个服务都需要与其他服务交互，但未定义通信机制
**建议**：
- 同步调用：使用 HTTP/REST（当前方案）
- 异步事件：使用消息队列（RabbitMQ/Kafka）
- 定义服务间接口契约（OpenAPI 规范）

### 2. 数据一致性
**问题**：跨服务数据更新可能不一致
**建议**：
- 使用分布式事务（Seata）或最终一致性
- 关键操作添加补偿机制
- 定期数据对账

### 3. 权限设计
**问题**：三个服务的权限点未统一管理
**建议**：
- 统一权限模型，避免重复定义
- 支持数据范围权限（科室、病区）
- 添加权限审计日志

### 4. 测试策略
**问题**：测试场景不够全面
**建议**：
- 添加集成测试（跨服务流程）
- 添加性能测试（并发场景）
- 添加安全测试（权限绕过、SQL 注入）

### 5. 文档完整性
**问题**：缺少部署和运维文档
**建议**：
- 添加部署架构图
- 添加配置说明（环境变量、数据库连接）
- 添加监控指标（Prometheus metrics）

2. 护理记录表结构优化

3. 结果批量导入（LIS）

1. 前端告警聚合
2. 体温单 PDF 导出
3. 危急值多渠道通知

## 六、总结

三份规格整体质量较高，架构设计合理，数据库设计符合规范。主要改进方向：

1. **性能**：添加缓存层，优化查询
2. **完整性**：补充异常处理和数据约束
3. **自动化**：减少手工操作，提升效率
4. **集成**：明确服务间通信机制
5. **运维**：补充部署和监控文档

建议按优先级逐步完善，优先解决影响实施的问题。
